# Value-Distribution Mechanisms, the Necessary Properties of Protocol, and the Iteration Path

> **The Evolution Archive · Part Three · Entry 9 (part finale)**. 09-23. Original text, sanitized; editor's note at the end.

---

**The questions**: three — ① how will value be distributed in the cognitive co-creation network ecosystem, and what mechanism should exist; ② a comparative analysis of Roblox / Steam Workshop / NieTa — what is each missing relative to the ideal co-creation network; ③ what necessary properties must the "externally grown protocol" have at the level of fundamental philosophy, and what is the iteration path.

## 1. Overview

Three questions, one line: **distribution (the attribution and flow of value) → comparison (which puzzle piece each existing form lacks) → protocol (what the structure carrying distribution and verification must itself be, and how it grows)**. Closing line: the cognitive co-creation network's unit of value distribution is the verifiable trajectory, not the product snapshot; reflow runs along the citation chain, not through platform skims; the protocol carrying it must have all five properties and retain its own right to die; the growth order is verification → mutual recognition → adjudication → distribution — four layers, none skippable.

## 2. The Value-Distribution Mechanism

### 2.1 Critique of the distribution unit: trajectory, not product

Existing platforms build all value distribution on **products**, but cognitive contribution is **chain-composed**: A's judgment cited by B, B's framework composed by C, C's output feeding D's agent — value passes along the citation chain and **emerges with delay** (an externalized experience may cash out in someone's workflow three months later). Price is instantaneous, settled on final products; the structural blind spot: **only the last mile is rewarded; the entire intermediate citation chain goes unpaid.**

Conclusion: this is not a question of distribution ratios — **the distribution unit is wrong.** The unit should be verifiable process contribution; the product snapshot is only the trajectory's terminal projection.

### 2.2 Critique of value compression: four value streams

| Type | Content | Property |
|------|------|------|
| Monetary value | Payment, revenue share | Instantly settleable |
| Reputation value | Process record (the barrier's thickness) | Cumulative, **non-transferable** (transferable = buying and selling reputation; unmoored) |
| Cognitive value | Others' cognition changed by you | Direct transmission of negentropy; most essential, hardest to meter |
| Relationship value | Collaboration history, trust network | Social capital |

The fundamental violence of existing platforms: compressing four-dimensional value into one-dimensional money, then monopolizing the exchange rate (Roblox's ~70% buy-in/cash-out spread is exchange-rate hegemony, not payment cost). **Monetization is not value distribution but value compression — and the compressor belongs to the platform.** The ideal mechanism's floor: all four value streams have their own reflow channels; none is forcibly routed through the monetary gate.

### 2.3 The three-layer mechanism

**Metering layer** (what counts as contribution), three signal sources: ① **the value-added differential** (the system-state difference before/after intervention — most essential and hardest; needs counterfactual baselines); ② **citation-through-use** (how often receipts / trajectories are *actually used* by others' workflows — machine-verifiable citation, not likes; the "call" behavior users spontaneously invented on a certain character platform is the wild prototype of exactly this behavior — merely unmetered); ③ **process reputation** (the quality accumulation of verifiable records, a long-cycle signal).

**Protocol layer** (how to split): the **reflow contract** settles automatically along the provenance graph — every value event triggers reflow along the citation chain. Analogy: **an economic automation of git blame**; no central settlement clerk; distribution is a protocol property.

**Settlement layer** (in what): fiat / credits / reputation all work; the key constraint is **auditable reflow paths**. No global ledger needed; blockchain only as the settlement layer's tamper-proof distribution ledger.

### 2.4 Two key designs

**① Layered visibility = the pricing function**: private contributions (the cognitive substrate) do not participate in reflow; public contributions (externalized trajectories) do — **how much process you open determines how much distribution you join.** Visibility negotiation is simultaneously value negotiation; sovereignty and distribution are two faces of one mechanism. Answer to "why should I open my process": opening is neither moral duty nor platform coercion — it is **the bid for entering the reflow.**

**② Commons pool / commons tax**: part of emergent value reflows into a commons pool specifically pricing **maintenance-grade entropy reduction** — documentation, maintenance, arbitration, education: contributions with "no direct consumption value but necessary for network survival." This directly solves the "dirty work undone" lesson and open-source maintainer exhaustion: if the distribution mechanism does not pay for maintenance, the network is eaten hollow by consumptive contributions.

### 2.5 Honest difficulties

- **Attribution is a counterfactual problem**: exact metering is impossible in principle. The goal degrades to **approximate fairness + auditability** — trading verifiability for precision; the error is a system cost.
- **The Matthew effect**: early contributors have the longest citation chains; reflow snowballs — needs time decay or generational balancing.
- **Sybil attacks**: gaming contributions presupposes forgeable contributions — the unforgeable layer is not a security feature but **the foundation of the distribution mechanism.**

## 3. Three-Platform Comparison

### 3.1 The verification-interrogation matrix

| Dimension | Roblox | Steam Workshop | NieTa | Ideal network |
|------|--------|-----------|------|--------------|
| Verification question | ✗ product signals only | △ subscription-as-vote (consumption side; no process layer) | ✗ none | process receipts mutually verified |
| Reflow question | ✗ one-way gate | ✗ mods bound to games | ✗ memory / relationships locked | assets portable; a hard protocol clause |
| Distribution | terminal revenue share, platform sets prices unilaterally | ~25% on item trades | **zero distribution** | reflow along the citation chain |
| Dirty-work pricing | ✗ | ✗ | ✗ | commons pool |

### 3.2 What each lacks

- **Roblox lacks sovereignty**: it proved the co-creation economy can scale (the only one to make "ordinary people earn a living by creating" work), but the platform is employer + market + currency issuer, a triple monopoly — **it built the co-creation economy and put it in a cage.**
- **The Workshop lacks "protocol before market"**: the 2015 paid-mods collapse in five days is a permanent lesson — **once a creative ecosystem has formed under free-reciprocity norms, monetization reads as predation.** The timing is irreversible; arriving late is taxation. Design constraint: **the reflow contract must be written into the protocol before the ecosystem forms; retrofitted patches necessarily rebound.**
- **NieTa lacks the substrate**: narratively closest to the ideal (consumption as creation), and the "call" behavior proves the citation chain is not a designed demand but **an already-existing, unsettled behavior.** But the implementation is pure platform: zero distribution, cognitive assets locked. Of the three, the widest "ecosystem narrative × platform implementation" gap.

### 3.3 Closing: external protocol growth

All three lack the protocol layer. **Platforms will not evolve there on their own** (the incentive structure: self-revolution = surrendering exchange-rate hegemony); hence the ideal co-creation network can only grow as an **external protocol** — as email / web were to AOL. A protocol cannot be born inside a profit center; it can only grow from the edges — open source / standards / personal substrates.

## 4. The Necessary Properties of Protocol

### 4.1 Ontological position

The protocol exists at no single node, only in the fact of "being jointly executed by many parties" — **a pure emergent, with no owner.** A platform is a private entropy barrier (order owned by shareholders); a protocol is a public entropy barrier (order owned jointly by all executors). **The protocol is culture made explicit and executable.** Historical regularity: at every computing-paradigm shift, private platforms appear first, and public protocols eat the platforms afterward (protocols permit competition among orders: implementations compete; the protocol wins).

### 4.2 The necessary properties (derived axiom by axiom)

| Property | Derived from | Content |
|------|--------|------|
| **① Trajectory** | Process axiom | The data unit is the trajectory, not the snapshot; append-only. **Applies recursively to the protocol itself**: the protocol's version history must be a trajectory — evolution by append only, no restarts (XHTML 2.0 wanted to restart HTML and died; the living standard lives) |
| **② Minimality** | Experience axiom | Intelligence grows in interaction → the protocol must leave maximal room for emergence → **fewest conventions, most emergence**. A hard constraint on the designer's ego: **a protocol is not the expression of its designer's wisdom but the soil an ecosystem grows in — the virtue of soil is barrenness, not fertility** |
| **③ Forkability** | Sovereignty axiom | No node holds final interpretive authority; right of exit (assets fully portable) + right to fork. **The protocol must allow its own opposition to exist — written into its own constitution** |
| **④ Built-in verification** | Reality axiom | Key claims independently verifiable by third parties; the root of trust is mathematics, not institutions. Priority: **better weak in function than weak in verification** — every distribution and consensus on a forgeable protocol will be corroded by sybil attacks |
| **⑤ Metabolism** | Entropy-reduction economics | The protocol is a dissipative structure, not a monument: built-in retirement channels + **maintenance costs made explicit** (who pays the entropy-reduction bill written at design time). A protocol without a built-in funding stream dies of maintainer exhaustion |

### 4.3 Closing: the protocol must be able to die

**The protocol must retain the freedom to be replaced, forked, and to die — a protocol that does not allow its own death will itself grow into Sobornost.** The first-generation protocol will most likely die, but **the testament clauses are written in advance** (open data formats, documented migration paths) — Gopher died and the hyperlink lives on in HTTP; a dead protocol must be inheritable by trajectory, as dead individuals leave their experience to the species.

## 5. The Iteration Path

### 5.1 The law of retrospective demand

Protocols are not born for "cognitive co-creation"; they are born for a single-point pain, then discovered to be that big protocol (HTTP for document sharing, git for managing the kernel). **The need's name is always retrospective.** The first step is inevitably disappointingly plain — self-use polished until it is indispensable (the Linus pattern: the first user is yourself; the second is a community attracted by quality).

### 5.2 The four layers cannot be skipped: verification → mutual recognition → adjudication → distribution

Each layer presupposes the previous. Skippers all died — historical autopsies: **Workshop monetization** = jumping to distribution before the ecosystem formed, collapse in five days; **the ICO craze** = skipping verification, settling directly, rotting in speculation; **the MCP ecosystem** = interoperability only, no verification, left hanging.

### 5.3 The current vacancy (the key observation)

The agent-protocol race (MCP / ACP / A2A / ANP) **all solve "interoperability" (how to talk); none solves "verification and attribution" (how to trust, how contributions count).** The counterintuitive corollary: **interoperability without verification helps platforms consolidate** — migration is free but value metering stays in platform hands: **free migration + metering monopoly = platform capture with a new posture.** The vacancy is not no-man's-land dividend; it is **a position that, left unfilled, reversely fortifies the opponent.**

### 5.4 The driver: a history of the expanding verifiable domain

| Stage | Verifiable domain | Status |
|------|---------|------|
| Done | Code execution (CI/CD) | Mature for 30 years |
| Happening | LLM / agent process (trace / receipts) | Underway |
| Next | Inter-agent citation (provenance graph) | Vacant |
| Long term | Judgment quality (value-added differential / counterfactual baselines) | Hardest; paradoxically engineerable in the agent era (two branches run the same task; the performance gap is the signal) |

### 5.5 The critical point: the structural crossover of coordination costs

**A platform's coordination cost is a function of people; a protocol's is a function of protocol.** Agent density grows → platform human-governance cost rises linearly → protocol automatic verification barely rises. The crossover arrives when agent count exceeds platform governance capacity — the moment web pages became richer than AOL portals, replayed. The trigger is not "the protocol is nicer to use" but **"the platform can no longer keep up."**

### 5.6 Time scales (the honest version)

Estimates: a de facto receipt-layer standard's prototype within 1–2 years; provenance + distribution layer in 3–5; a mature ecosystem in 5–10. The first-generation protocol will most likely die en route (the maintenance bill unpayable); the testament clauses guarantee inheritable trajectories — **this generation's work is not to build it, but to lay the first stretch of trajectory worth inheriting.**

## 6. Open Questions (left for the next layer)

- **The metering-precision advantage**: the value-added differential is engineerable in agent networks (two-branch A/B on the same task) — does this mean the agent era's value-metering precision will surpass the human-collaboration era (a human colleague's contribution was never meterable)? If so, "collaboration with precisely meterable contribution" may become the co-creation network's core competitive advantage over the firm system — a disruption deeper than distribution ratios.
- **Minimality vs. built-in verification**: verification requires the protocol to specify formats / signatures / revocation — each adds weight (anti-minimality). Leaning: a layered verification protocol (minimal core = unforgeable event existence; periphery = optional semantic annotation); how small the minimal core can get is the real design difficulty.
