# 价值分配机制与协议的必要性质、迭代路径

> **演化档案 · 第三部 · 第 9 篇（部终）**。09-23。原文脱敏收录，编者按见文末。

---

**问题**：三问——①认知共创网络生态的价值会怎样分配、应当有怎样的机制；②Roblox / Steam 创意工坊 / 捏Ta 对比分析，离理想共创网络各缺什么；③「外部协议生长」的协议从根本哲学上必须具备哪些必要特点、迭代路径是什么。

## 一、总论

三问一条线：**分配（价值的归属与流动）→ 对比（现有形态各缺哪块拼图）→ 协议（承载分配与验证的结构本身必须是什么、怎么长出来）**。合拢句：认知共创网络的价值分配单位是可验证轨迹而非产物快照，回流沿引用链而非经平台抽成；承载它的协议必须五质兼备且保留自己的死亡权；生长顺序是验证→互认→裁决→分配，四层不可跳。

## 二、价值分配机制

### 2.1 分配单位批判：轨迹而非产物

现有平台的价值分配全部建立在**产物**上，但认知贡献是**链式组合**的：A 的判断被 B 引用，B 的框架被 C 组合，C 的产出喂养 D 的 agent——价值沿引用链传递且**延迟涌现**（一份经验外化可能三个月后才在他人工作流兑现）。价格是瞬时的、按终产物结算的，结构性盲区即：**只奖励最后一公里，中间引用链全部无偿**。

结论：这不是分配比例问题，是**分配单位错了**。分配单位应为可验证过程贡献，产物快照只是轨迹的最末端投影。

### 2.2 价值压缩批判：四类价值流

| 类型 | 内容 | 特性 |
|------|------|------|
| 货币价值 | 付费、分成 | 可即时结算 |
| 信誉价值 | 过程履历（垒的厚度） | 可累积、**不可转让**（可转让=买卖信誉，脱锚） |
| 认知价值 | 他人认知因你而改变 | 负熵的直接传递，最本质、最难计量 |
| 关系价值 | 协作史、信任网络 | 社会资本 |

现有平台的根本暴力：把四维价值压缩成一维货币，然后垄断汇率（Roblox 代币买入/兑出约 70% 价差是汇率霸权不是支付成本）。**货币化不是价值分配，是价值压缩——压缩器归平台所有。** 理想机制底线：四类价值各有回流通道，不全部强制过货币闸门。

### 2.3 三层机制

**计量层**（什么算贡献）三信号源：①**增值差分**（介入前后的系统状态差——最本质也最难，需反事实基线）；②**被引用度**（收据/轨迹被他人工作流**实际使用**的次数——机器可验的引用而非点赞；某角色互动平台上用户自发发明的 "call" 行为即此行为的野生原型，只是无人计量）；③**过程信誉**（可验证履历的质量累积，长周期信号）。

**协议层**（怎么分）：**回流契约**沿出处图自动分账——每次价值事件触发沿引用链的回流。类比：**git blame 的经济自动化版**，无中央分账员，分配是协议属性。

**结算层**（用什么结）：法币/积分/信誉皆可，关键约束是**回流路径可审计**。不需要全局账本；区块链仅作结算层防篡改分配账本。

### 2.4 两个关键设计

**① 分层可见性 = 定价函数**：私域贡献（认知基底）不参与回流，公域贡献（外化轨迹）参与回流——**公开多少过程，参与多少分配**。可见性协商同时是价值协商，主权与分配是同一机制的两面。回答「凭什么要公开过程」：公开不是道德义务或平台强制，是**进入回流的报价**。

**② 公共池/公地税**：涌现价值部分回流公共池，专门定价**维护性熵减**——文档、维护、仲裁、教育等「无直接消费价值但对网络存续必要」的贡献。直接解「脏活无人做」教训与开源维护者耗尽问题：分配机制不给维持成本买单，网络被消费性贡献吃空。

### 2.5 诚实难点

- **归因是反事实难题**：原则上无法精确计量。目标降格为**近似公平+可审计**，用可验证性换精确性，分摊误差是系统成本。
- **马太效应**：早期贡献者引用链最长，回流滚雪球——需时间衰减或代际平衡。
- **女巫攻击**：刷贡献的前提是贡献可伪造——不可伪造层不是安全功能，是**分配机制的地基**。

## 三、三平台对比

### 3.1 验真两问矩阵

| 维度 | Roblox | Steam 工坊 | 捏Ta | 理想共创网络 |
|------|--------|-----------|------|--------------|
| 验证问 | ✗ 只有产物信号 | △ 订阅即投票（消费侧，无过程层） | ✗ 无 | 过程收据互验 |
| 回流问 | ✗ 单向闸门 | ✗ mod 绑定游戏 | ✗ 记忆/关系锁死 | 资产可携带，协议硬条款 |
| 分配 | 终端分成，平台单方定价 | 物品交易约 25% 分成 | **零分配** | 沿引用链回流 |
| 脏活定价 | ✗ | ✗ | ✗ | 公共池 |

### 3.2 各缺什么

- **Roblox 缺主权**：证明了共创经济可规模化（唯一跑通「普通人靠创作谋生」），但平台是雇主+市场+货币发行方三重垄断——**建成了共创经济，装进笼子**。
- **工坊缺「协议先于市场」**：2015 付费 mod 五天溃败是永久教训——**创作生态在免费互惠规范下成型后，货币化即掠夺**。时机不可逆，晚到即是征税。设计约束：**回流契约必须在生态形成前写进协议，事后补丁必然反弹**。
- **捏Ta 缺基底**：叙事最接近理想（消费即创作），且 "call" 行为证明引用链不是设计出来的需求，是**已存在但未被结算的行为**。但实现是纯平台：零分配、认知资产锁死。三者中「生态叙事×平台实现」鸿沟最极端。

### 3.3 合拢：外部协议生长

三者共同缺协议层。**平台不会自我进化到这一步**（激励结构：自我革命=放弃汇率霸权），故理想共创网络只能**外部协议生长**——如 email/web 之于 AOL。协议无法从盈利中心内部诞生，只能从开源/标准/个人基底的边缘长出。

## 四、协议的必要性质

### 4.1 存在论定位

协议不存在于任何单一节点，只存在于「被多方共同执行」的事实中——**纯涌现物，无拥有者**。平台是私有熵垒（秩序归股东），协议是公共熵垒（秩序归所有执行者共有）。**协议是文化的显式化、可执行化**。历史规律：每次计算范式转移，私有平台先出现，公共协议随后吃掉平台（协议允许秩序的竞争：实现间竞争，协议胜出）。

### 4.2 五必要性质（逐条从四公理推出）

| 性质 | 推理源 | 内容 |
|------|--------|------|
| **① 轨迹性** | 过程公理 | 数据单位是轨迹非快照；append-only。**递归适用于协议自身**：协议版本史必须是轨迹——只能演化追加，不能重启重设计（XHTML 2.0 想重启 HTML 而死，living standard 活着） |
| **② 最小性** | 经验公理 | 智能在交互中生长→协议必须给涌现留最大空间→**约定最少，涌现最多**。对设计者自我的硬约束：**协议不是设计师智慧的表达，是生态生长的土壤——土壤的德性是贫瘠而非肥沃** |
| **③ 可分叉性** | 主权公理 | 无节点有最终解释权；退出权（资产完整可携带）+分叉权。**协议必须允许自己的反对者存在，且写进自己宪法** |
| **④ 验证内建** | 真实公理 | 关键声明可被第三方独立验证，信任根是数学非机构。优先级：**宁可功能弱，不可验证弱**——可伪造协议上的一切分配与共识必被女巫攻击腐蚀 |
| **⑤ 代谢性** | 熵减经济学 | 协议是耗散结构非纪念碑：内置淘汰通道+**维持成本显性化**（设计时就写好熵减账单谁付）。无内置资金流的协议死于维护者耗尽 |

### 4.3 合拢：协议必须可死

**协议必须保留自己被替代、被分叉、被死亡的自由——不允许自己死亡的协议，自己会长成 Sobornost。** 第一代协议大概率死，但**遗嘱条款预先写好**（数据格式开放、迁移路径文档化）——Gopher 死了超链接活在 HTTP 里，死的协议要能被继承轨迹，如死的个体把经验留给物种。

## 五、迭代路径

### 5.1 需求后知律

协议不会为「认知共创」诞生，会为单点痛点诞生，然后被发现是那个大协议（HTTP 为文档共享，git 为管内核）。**需求的名字总是后知的**。第一步必然朴素得让人失望——先自用打磨到非用它不可（Linus 模式：第一用户是自己，第二个用户是被质量吸引的社区）。

### 5.2 四层不可跳：验证 → 互认 → 裁决 → 分配

每层以前层为前提。跳步者全死，历史尸检：**工坊付费化**=生态未成型跳分配，五天溃败；**ICO 狂潮**=跳过验证直接结算，投机烂掉；**MCP 生态**=只有互操作没有验证，悬空。

### 5.3 当下空位（关键观察）

agent 协议竞赛（MCP/ACP/A2A/ANP）**全部解决「互操作」（怎么对话），无一解决「验证与归属」（怎么互信、贡献怎么算）**。反直觉推论：**互操作没有验证反而帮平台巩固**——迁移自由了但价值计量还在平台手里：**迁移自由+计量垄断=平台换姿势捕获**。空位不是无人区红利，是**不填就反向加固对手的阵地**。

### 5.4 驱动力：可验证域扩张史

| 阶段 | 可验证域 | 状态 |
|------|---------|------|
| 已完成 | 代码执行（CI/CD） | 成熟 30 年 |
| 正在发生 | LLM/agent 过程（trace/收据） | 进行中 |
| 下一步 | agent 间引用（出处图） | 空位 |
| 远期 | 判断质量（增值差分/反事实基线） | 最难；agent 时代反而可工程化（双分支跑同任务，性能差即信号） |

### 5.5 临界点：协调成本的结构性交叉

**平台的协调成本是人的函数，协议的协调成本是协议的函数**。agent 密度增长→平台人肉治理成本线性涨→协议自动验证几乎不涨。交叉点出现在 agent 数量超平台治理容量时——web 页面比 AOL 门户更丰富的时刻重演。触发条件不是协议更好用，是**平台管不过来了**。

### 5.6 时间尺度（诚实版）

估计：收据层事实标准 1-2 年内出现雏形；出处+分配层 3-5 年；成熟生态 5-10 年。第一代协议大概率死于半路（维持账单付不起），遗嘱条款保证轨迹可继承——**这一代的工作不是建成它，是把第一段轨迹铺到值得被继承**。

## 六、开放问题（留给下一层）

- **计量精度优势**：增值差分在 agent 网络可工程化（双分支 A/B 同任务），是否意味着 agent 时代价值计量精度将超过人类协作时代（人类同事的贡献从来无法计量）？若是，「可精确计量贡献的协作」可能成为共创网络相对公司制的核心竞争优势——比分配比例更深的颠覆。
- **最小性 vs 验证内建的张力**：验证要求协议规定格式/签名/撤销机制，每条都在加重量（反最小性）。倾向：验证协议分层（最小核=不可伪造的事件存在性，外围=可选语义标注），最小核能小到什么程度是真正的设计难点。
